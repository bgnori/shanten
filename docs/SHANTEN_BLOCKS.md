# 面子手におけるブロック用語

## 目的

この文書は、面子手のシャンテン計算およびLean形式証明で用いる
「面子」「搭子」「ブロック」「雀頭」の関係を整理する。

特に、未完成の手牌を「4面子」と表現すると、搭子を含むDP状態を正確に
表せない。そのため、面子手の分解では「4ブロック」と「雀頭」を基本的な
表現として用いる。

## 基本用語

### 面子

完成した3枚の組をいう。

- 順子: 同じ種類で連続する3枚
- 刻子: 同じ牌3枚

本リポジトリのLeanモデルでは、完成面子を `Meld` として表す。
槓も、固定面子としては1つの面子として数える。ただし、現在の `Hand` は
固定面子の個数だけを保持し、固定面子の牌内容は保持していない。

### 搭子

あと1枚加えることで面子になる、未完成の2枚組をいう。

現在の面子手DPでは、次の搭子を扱う。

- 対子形搭子: 同じ牌2枚。もう1枚加えると刻子になる。
- 両面・嵌張などの順子形搭子: 同じ種類の2枚。もう1枚加えると順子になる。

`7,8` のように3枚目を前に補う必要がある場合も、搭子として扱う。
例えば `7,8` に `6` を加えて `6,7,8` とする。

### ブロック

面子手の面子部分を構成する、次のいずれかの候補をいう。

- 完成面子
- 搭子

したがって、DP上の面子系ブロック数は次で表される。

```text
完成面子数 + 搭子数
```

固定面子も、完成済みの面子ブロックとして数える。

### 雀頭

同じ牌2枚からなる対である。面子手では、面子系ブロックとは別に
ちょうど1つの雀頭が必要になる。

DPでは、雀頭の有無を `StandardSearchState.pair : Option Tile` で表す。

## 面子手の構造

面子手の完成形は、次のように表す。

```text
面子系ブロック 4個 + 雀頭 1個
```

完成後は、4つのブロックがすべて完成面子になる。

全体を単純に部品数として数える場合は、

```text
4面子 + 1雀頭 = 5ブロック相当
```

と表現することもできる。ただし、シャンテン計算やDPでは、雀頭を面子系
ブロックと別に管理するため、基本表現は **4ブロック＋雀頭** とする。

## DP状態との対応

[`Shanten/Standard.lean`](../Shanten/Standard.lean) の
`StandardSearchState` には、面子手の分解が次のように記録される。

| DP状態 | 意味 |
|---|---|
| `pair : Option Tile` | 雀頭候補 |
| `meldHistory : List Meld` | すでに完成している面子ブロック |
| `taatsuHistory : List Taatsu` | 未完成の搭子ブロック |
| `melds` | `meldHistory` の個数 |
| `taatsu` | `taatsuHistory` の個数 |
| `hand.fixedMelds` | すでに固定されている面子ブロックの個数 |

したがって、面子手を構成するためのブロック数条件は、

```lean
state.melds + state.taatsu + hand.fixedMelds = 4
```

である。

さらに、

```lean
state.pair.isSome
```

が必要である。

この2つを合わせると、

```text
面子ブロック + 搭子ブロック = 4
雀頭 = 1
```

となり、面子手の部品数が揃う。

## 搭子を面子へ変換する処理

DPが選択した搭子は、必要な1枚を補うことで完成面子になる。

[`taatsuCompletionTile`](../Shanten/Standard.lean) は補充すべき牌を、
[`taatsuCompletionMeld`](../Shanten/Standard.lean) は補充後の面子を構成する。

搭子履歴全体については、次の変換を行う。

```text
taatsuHistory
  -> taatsuCompletionMelds taatsuHistory
```

この変換について、次の性質を証明している。

- 各搭子に補充牌を加えると、対応する完成面子の牌集合になる
- 搭子履歴全体に補充牌を加えると、完成面子列の牌集合になる
- 完成面子列の長さは、元の面子数と搭子数の合計になる

したがって、4ブロック条件が成立していれば、搭子を実際の面子へ変換して
面子手の完成形の4面子を構成できる。

## シャンテン計算との関係

シャンテン計算では、次の値を区別して扱う。

```text
m = 完成面子数
t = 搭子数
p = 雀頭があるか
```

面子系ブロックについては、5個以上を数えても面子手では4個までしか
有効ではない。そのため、概念的には次のように扱う。

```text
有効な面子系ブロック数 = min(m + t, 4)
```

雀頭は別枠で扱う。

面子手の完成条件は次のようになる。

```text
min(m + t, 4) = 4
かつ p = 1
```

ただし、実際のDP状態では固定面子も含める必要があるため、より正確には、

```text
min(m + t + fixedMelds, 4) = 4
かつ p = 1
```

と考える。

## 用語の使い分け

今後のドキュメント、定理名、コメントでは、次の使い分けを基本とする。

### 「4面子」と表現する場合

すでにすべて完成している最終形だけを指す。

例:

```text
面子手の完成形は4面子1雀頭である。
```

### 「4ブロック」と表現する場合

完成面子と搭子を混在させた、未完成状態の面子系部品を指す。

例:

```text
DPは完成面子と搭子を合わせて4ブロックを構成する。
```

### 「4ブロック＋雀頭」と表現する場合

面子手の分解全体を指す。今回の形式証明では、この表現を最も基本的な
表現とする。

## 現在の実装に関する注意

現在の `IsStandardSearchComplete` は、歴史的に次の条件を使っている。

```lean
state.melds + hand.fixedMelds = 4 ∧ state.pair.isSome
```

これは搭子を完了条件に含めない、より強い条件である。

搭子を含む一般的なブロック分解を表すには、次の条件が本来の意味に近い。

```lean
state.melds + state.taatsu + hand.fixedMelds = 4 ∧
state.pair.isSome
```

今後、DPの完了条件や最終定理を整理するときは、後者を「4ブロック＋雀頭」
の条件として扱う。ただし、既存の定義を変更する際には、既存の到達性補題と
`Bounds.lean` のインターフェースを同時に更新する必要がある。

## まとめ

面子手について、本リポジトリでは次の表現を正とする。

```text
完成形:       4面子 + 1雀頭
未完成分解:   4ブロック + 1雀頭
ブロック:     完成面子または搭子
DPの面子系数: 完成面子数 + 搭子数 + 固定面子数
```

この用語を使うことで、「搭子を含むDP分解」と「最終的な4面子1雀頭」を
混同せずに、シャンテン計算と構成的証明を記述できる。
